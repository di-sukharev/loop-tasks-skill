# loop-tasks-skill

`loop-tasks` — агентный скилл для последовательного выполнения пачки связанных задач. Оркестратор не трогает код: он выдаёт каждую задачу отдельному свежему рабочему агенту, обрабатывает внутренние зависимости и пропускает задачу дальше только после ревью, коммита, push и чистого рабочего дерева.

Рабочий агент сам вызывает [`loop-code-review`](https://github.com/di-sukharev/loop-code-review-skill) и исправляет только P0/P1: ошибки поведения, регрессии, уязвимости, потерю данных, нарушения контрактов и проверки, сломанные изменениями задачи. Стиль, нейминг и необязательные рефакторинги не задерживают цикл.

## Установка

Сначала установите `loop-code-review`, затем скопируйте папку `loop-tasks` из этого репозитория в каталог скиллов.

Codex:

```sh
mkdir -p ~/.codex/skills
cp -R loop-tasks ~/.codex/skills/
```

Claude Code:

```sh
mkdir -p ~/.claude/skills
cp -R loop-tasks ~/.claude/skills/
```

## Использование

- `$loop-tasks` в Codex;
- `/loop-tasks` в Claude Code;
- либо попросите агента последовательно выполнить весь переданный список задач через свежих саб-агентов.

Перед запуском нужен чистый Git worktree и настроенный push текущей ветки. В конце скилл перечисляет выполненные задачи, созданные коммиты и ветку назначения.

### Модели для кода и ревью

Для написания кода можно взять быстрого и дешёвого саб-агента, а для код-ревью —
более умного и дорогого саб-саб-агента. Модели задаются отдельно на каждый запуск:

```text
$loop-tasks --sub gpt-5.6-luna --sub-sub gpt-6-astra
Последовательно выполни все открытые задачи из tasks/.
```

Это пример для Codex, где доступны обе модели. Подставляйте идентификаторы моделей
из своего приложения. `--sub` выбирает исполнителя, `--sub-sub` —
ревьюера на каждом проходе. Можно передать один параметр или оба; запись
`--sub=MODEL` тоже поддерживается. Оркестратор остаётся на модели текущего
диалога.

Флаги здесь — договорённость внутри промта скилла. Агент читает их и передаёт
значения в инструмент запуска саб-агентов; это не команда для терминала. Можно
написать то же самое обычным текстом: «Для реализации используй gpt-5.6-luna,
для каждого ревью — gpt-6-astra».

Без параметра соответствующая роль использует настройки и наследование модели
своего приложения. Поэтому при указании только `--sub` ревьюер тоже
может унаследовать модель исполнителя. Если хотите разделить модели, явно укажите
`--sub-sub`. Если выбранная модель или вложенные саб-агенты недоступны,
скилл сообщит `BLOCKED`; молча заменять модель он не должен.

После обновления исходников повторите копирование из раздела установки, чтобы
обновить уже установленный скилл.
