# loop-tasks-skill

`loop-tasks` последовательно выполняет пачку задач через свежих рабочих агентов без истории родительского диалога. Оркестратор ведёт очередь по коротким отчётам, не читая код, диффы, логи и историю агентов. Исполнители отвечают за реализацию, проверки, ревью, коммит и push.

Исполнитель вызывает [`loop-code-review`](https://github.com/di-sukharev/loop-code-review-skill) с явным ограничением каждого ревьюера до обоснованных P0/P1. Все требования задачи должны быть выполнены независимо от приоритета замечаний.

## Установка

Сначала установите `loop-code-review`, затем скопируйте папку `loop-tasks` из этого репозитория в каталог скиллов.

Codex:

```sh
mkdir -p ~/.codex/skills
cp -R loop-tasks ~/.codex/skills/
```

Claude Code:

```sh
mkdir -p ~/.claude/skills
cp -R loop-tasks ~/.claude/skills/
```

## Использование

- `$loop-tasks` в Codex;
- `/loop-tasks` в Claude Code;
- либо попросите агента последовательно выполнить весь переданный список задач через свежих саб-агентов.

Перед запуском нужен чистый Git worktree и настроенный push текущей ветки. В конце скилл перечисляет выполненные задачи, созданные коммиты и ветку назначения.

### Скорость и контекст

Исполнитель проверяет Git на входе и выходе. Во время реализации он запускает узкие проверки, перед коммитом — применимый полный прогон. Успешные проверки неизменённого состояния и команды внутри составного прогона не дублируются. Оркестратор продолжает очередь после подтверждения успешного push и чистого дерева.

После заметных задержек исполнитель кратко сообщает причину и полезную корректировку процесса. Оркестратор применяет её к следующим задачам, когда уместно, и хранит лишь актуальные рекомендации. Адаптация не ослабляет требования и не меняет выбранные модели.

### Модели для кода и ревью

Модели исполнителя (`--sub`) и каждого ревьюера (`--sub-sub`) задаются независимо:

```text
$loop-tasks --sub gpt-5.6-luna --sub-sub gpt-6-astra
Последовательно выполни все открытые задачи из tasks/.
```

Подставляйте доступные в своём приложении модели. Можно указать один параметр или
оба, использовать запись `--sub=MODEL` / `--sub-sub=MODEL` или назвать модели
обычным текстом. Оркестратор остаётся на модели текущего диалога.

Это соглашение внутри промта скилла: агент передаёт модели инструменту запуска
саб-агентов, а не выполняет команду в терминале.

Без параметра действует выбор и наследование модели приложения; ревьюер может
унаследовать модель исполнителя. Если выбранная модель или вложенные саб-агенты
недоступны, скилл возвращает `BLOCKED` без подмены модели.

После обновления исходников повторите копирование из раздела установки, чтобы
обновить уже установленный скилл.
